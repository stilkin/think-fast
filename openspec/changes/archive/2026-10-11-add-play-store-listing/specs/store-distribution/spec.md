# store-distribution Delta

## ADDED Requirements

### Requirement: The Play Store listing lives in the repository and is pushed through the Publishing API
The Google Play listing content SHALL live in the repository — copy in `play.config.json`, images as script-generated or reused assets — and SHALL reach the store only through the Google Play Developer Publishing API's transactional edits (one edit, one commit). Store-side fields with no API SHALL be entered manually in Play Console and enumerated in the repository. The listing SHALL stay in line with the App Store listing where both exist.

#### Scenario: Listing content is reproducible from the repo
- **WHEN** the Play listing copy or images need a change
- **THEN** they are edited in `play.config.json` / regenerated by script and pushed by `scripts/play-push-listing.mjs` — nothing is hand-entered on the store side except fields Play exposes no interface for

#### Scenario: Pushes are transactional and careful
- **WHEN** the listing is pushed
- **THEN** all changes (language, text, images) are staged in a single uncommitted edit; any failure aborts before commit and deletes the edit; the push never retries, and the result is verified by reading the listing back

#### Scenario: The manual remainder is explicit
- **WHEN** the listing is complete
- **THEN** the Play-console-only items (app-content questionnaires, privacy-policy URL, pricing/availability, app category) are enumerated in the repository rather than silently diverging from it
